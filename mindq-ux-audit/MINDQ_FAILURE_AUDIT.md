# MindQ Failure-Mode Audit

**Date:** 2026-11-26 · **Branch:** `qa` (working tree incl. uncommitted changes) · **Mode:** read-only, no application code modified

## Scope & method

An adversarial review of `backend/`, `frontend/src/`, `supabase/migrations/`, and the infra files in the repo (`backend/Dockerfile`, `frontend/Dockerfile`, `docker-compose.yml`, `DEPLOYMENT.md`, `.github/workflows/ci.yml`). It looks for every realistic way the platform can crash, hang, lose candidate data, leak across tenants, or become unavailable under 50–200 concurrent candidates. Every finding cites exact file and line numbers. The highest-impact findings were re-read against source after the initial sweep.

**Not inspectable:** the repo contains no nginx, systemd, or logrotate configs for the hosts `172.26.7.203` / `172.26.25.34`. Nginx appears only as prose in `DEPLOYMENT.md:147`. Proxy timeouts, body limits, restart policies, and log rotation on those hosts are therefore **unverified** (see P2-12).

All paths below are repo-relative. `backend/app/` is abbreviated as `app/`.

## Summary

| Severity | Count | Meaning |
|---|---|---|
| **P0** | 8 | Outage, data loss, or security breach. Must fix before launch. |
| **P1** | 20 | Degraded UX or silent failure under load. Fix before scaling past pilot. |
| **P2** | 12 | Hardening and edge cases. Backlog. |

**Top 3 risks**
1. **Candidate results are silently never scored** (P0-01, P0-02). Any autosave that lands after the deadline finalizes the module without queueing scoring, and scoring failures are swallowed with no retry or reconciler.
2. **Login-burst outage** (P0-05, P0-06). The connection budget is already at the Supavisor cap before counting ARQ, and candidate OTP send holds a DB connection across the SES call.
3. **Deployability and infra security** (P0-04, P0-07). Three migrations are git-ignored, and Redis has no auth while ARQ uses pickle.

## P2: Hardening / Edge Cases

| ID | Layer | Failure Scenario | Exact File & Line | Trigger Condition | Concrete Fix |

| **P2-01** | Queue | ARQ retries only on `Retry` or interruption, so `ARQ_MAX_TRIES=3` is largely moot.
